# 002. Harbor Web Agent Evals

Define the smallest Harbor-compatible execution and scoring surface needed to
evaluate trusted web-search, web-fetch, and browser-control agents from this
repository.

## Scope

- Harbor `0.18.0` custom `BaseEnvironment` and `BaseAgent` plugins in an
  independently installable Python package under `tools/psycheval-harbor/`
- Linux host-process execution for trusted local tasks, selected explicitly by
  the Harbor CLI
- a generic external harness contract that receives the task instruction on
  stdin and must write an ATIF v1.7 trajectory
- a Psychevo harness that runs the real `pevo run --format json` command and
  converts its typed transcript to ATIF without reading Psychevo's state
  database or changing Psychevo's source tree; the invoked `pevo run` retains
  its normal session-persistence behavior
- a minimal Harbor Task template and executable examples for web search, web
  fetch, and browser control
- deterministic local verifier fixtures by default and opt-in live web-search
  and web-fetch Tasks for Psychevo
- outcome-and-evidence grading with one binary reward key and detailed checks

Out of scope:

- running untrusted Tasks or harnesses
- security isolation, privilege separation, filesystem confinement, credential
  filtering, or network sandboxing
- Windows and macOS host execution
- Docker Compose, sidecars, service operations, extra mounts, GPUs, TPUs,
  CPU/memory/storage enforcement, network allowlists, or no-network Tasks
- compatibility with arbitrary Harbor Tasks, agents, or verifier scripts
- browser automation support inside Psychevo
- changing Psychevo when a live evaluation exposes a Psychevo defect

## Harbor Compatibility Boundary

The package subclasses Harbor's public Python interfaces and is loaded through
the existing `--environment module:Class` and `--agent module:Class` CLI import
paths. It does not introduce a wrapper command or a parallel result format.

The supported Task subset is:

```text
task/
├── instruction.md
├── task.toml
├── environment/
│   └── Dockerfile
└── tests/
    ├── test.sh
    └── ...
```

`instruction.md`, `task.toml`, and `environment/` are required by Harbor's Task
loader. `tests/test.sh` is required by the default shared verifier. The
Dockerfile is retained so the same Task may fall back to Harbor's Docker
environment; HostEnvironment treats it as compatibility metadata and does not
build it. `solution/`, `steps/`, README files, metadata tables, explicit
artifact declarations, and RewardKit configuration are not required by this
subset.

Tasks use schema version `1.3`, the default shared verifier, and a POSIX shell
test script. The verifier must write `/logs/verifier/reward.json` in Docker or
the corresponding portable path in HostEnvironment. A verifier exit code alone
is not a reward.

## HostEnvironment

Host execution is an explicit unsafe mode. Construction fails unless Harbor is
passed `--environment-kwarg allow_host_execution=true`. This is consent to run
the Task, harness, and verifier as ordinary host subprocesses with the caller's
filesystem, environment, credentials, and public network access.

Each environment instance owns a unique temporary runtime root with these
logical locations:

| Harbor path | Host runtime path | Portable variable |
| --- | --- | --- |
| `/app` | `<root>/app` | `PSYCHEVAL_WORKDIR` |
| `/tests` | `<root>/tests` | `PSYCHEVAL_TESTS_DIR` |
| `/solution` | `<root>/solution` | none |
| `/logs/agent` | Harbor Trial agent directory | `PSYCHEVAL_AGENT_LOGS_DIR` |
| `/logs/verifier` | Harbor Trial verifier directory | `PSYCHEVAL_VERIFIER_LOGS_DIR` |
| `/logs/artifacts` | Harbor Trial artifact staging directory | `PSYCHEVAL_ARTIFACTS_DIR` |

HostEnvironment also sets `PSYCHEVAL_HARBOR_PYTHON` to the interpreter that
loaded the Harbor plugins, allowing the shared verifier script to invoke the
installed `psycheval_harbor` module. Docker execution falls back to `python3`
and therefore requires the package to be installed in the image.

`start()` creates these locations and copies the Task `environment/` contents
into the workdir. Upload and download operations translate only the documented
Harbor roots. Commands generated by Harbor are translated from those roots to
the corresponding host paths before `/bin/bash` execution. Translation
preserves a shell-token boundary around the complete replacement, including
when a host Trial path contains whitespace or shell metacharacters; it does not
rewrite matching substrings in URLs or descriptive strings. Task-owned scripts
must use the portable variables with Harbor path fallbacks instead of assuming
that root-level `/logs`, `/tests`, or `/app` can be created on the host.

The environment inherits host variables and then applies Harbor's persistent,
per-command, and scoped overlays. It invokes commands in their own process
group, streams stdout/stderr through Harbor callbacks, and terminates the whole
group on timeout or cancellation. Explicit user `root`, the current username,
and the current uid mean the current host process; other users are rejected.

HostEnvironment advertises only mounted host logs. Each supported log target
may appear at most once and must be the writable bind mount from the exact
Trial-owned host directory Harbor assigns to that target. It rejects duplicate
or substituted log mounts, Windows Tasks, Compose definitions, non-public
network policies, resource requests or enforcement, extra mounts, extra
Compose files, and `force_build=true`. It removes only its own temporary
runtime root when Harbor requests deletion.

## ExternalHarnessAgent

The generic agent accepts one required command through an agent kwarg. `setup()`
does not install software. `run()` executes the command in the Task workdir,
sends the exact Harbor instruction to stdin, and provides the portable path
variables. The command must exit successfully and write a valid ATIF v1.7 JSON
object to `$PSYCHEVAL_AGENT_LOGS_DIR/trajectory.json`. Missing, malformed, or
invalid trajectories are agent failures rather than verifier failures.

The agent reports a stable custom name and version, declares
`SUPPORTS_ATIF = true`, and leaves model selection to the external harness.
Harbor remains the owner of Trial lifecycle, timeout, result, and artifact
collection.

Harbor `0.18.0`'s `traces export` implementation rejects custom import-path
agent names before reaching its custom-agent fallback. This is an upstream CLI
consumer defect, not a Task, Trial, or ATIF format extension point. The plugin
must retain its truthful custom identity; it must not claim a built-in name to
bypass that check.

## Psychevo Harness

The Psychevo harness is a command usable by ExternalHarnessAgent. It resolves a
`pevo` executable from an explicit option or `PATH`, then runs:

```text
pevo run --format json --isolated --no-agents --no-skills <instruction>
```

The process inherits the user's configured live model/provider and web-search
backend. No API key is copied into Task files or Trial artifacts. Raw NDJSON is
retained in the agent log directory for diagnosis.

The converter uses typed transcript items as its fact source. Psychevo may emit
tool identity and arguments in an early item and a bounded, sanitized result in
the later completed item, so the converter merges lifecycle events only within
one started/updated/completed occurrence and only when it has one stable
tool-call identity. A later completed occurrence is retained even if Psychevo
reuses the same assistant item id.

Runtime tool projections use `metadata.tool_call_id`, `arguments`/`args`, and
their structured result. Hosted provider tools use
`metadata.provider_tool_id`, the complete `metadata.action` object as ATIF
arguments, their provider status, and the typed source blocks that follow that
provider tool in the same completed assistant occurrence as the observation.
Provider source blocks and assistant text are never reclassified as tool
results through an item-id fallback. The converter emits the user instruction,
every completed assistant message, tool calls, attached observations, and the
terminal final answer. A non-zero `pevo` exit, failed terminal event, missing
terminal event, missing tool-call identity, or malformed NDJSON fails the
harness visibly. The trajectory does not invent tool calls or observations
from prose.

Live Psychevo evaluation is opt-in because it contacts a configured real model
provider and the public web. A failed live Trial must be classified from its
Harbor logs, raw Psychevo transcript, ATIF trajectory when present, and relevant
Psychevo source. Infrastructure, provider, credential, target-site, and search
backend failures are reported separately from Psychevo implementation defects.
This repository does not modify Psychevo as part of that classification.

## Task and Harness Portability

All bundled scripts resolve paths like this:

```sh
agent_logs=${PSYCHEVAL_AGENT_LOGS_DIR:-/logs/agent}
verifier_logs=${PSYCHEVAL_VERIFIER_LOGS_DIR:-/logs/verifier}
artifacts=${PSYCHEVAL_ARTIFACTS_DIR:-/logs/artifacts}
workdir=${PSYCHEVAL_WORKDIR:-/app}
tests=${PSYCHEVAL_TESTS_DIR:-/tests}
```

The Task examples therefore run with either HostEnvironment or Docker when the
selected external harness is available in that environment. Host-only absolute
paths must be passed as CLI kwargs or environment variables, never committed to
Task definitions.

## Scoring Contract

Each example verifier reads the ATIF trajectory and evaluates observable
outcomes plus the minimum action evidence needed to attribute the outcome to
the Agent. Its `required_calls` rules form an ordered subsequence. Every rule
must be satisfied by one call whose tool name and arguments match and whose
observation for that same call id is present, non-error, and contains the
required evidence. Evidence from different calls cannot be combined. It does
not grade hidden chain-of-thought or require actions beyond that declared
subsequence.

- Web search requires an actual `web_search` tool call, query semantics relevant
  to the instruction, a successful search observation containing the expected
  source or fact, and a final answer containing the requested fact/citation.
- Web fetch requires an actual `web_fetch` tool call with the normalized target
  URL, a successful observation containing the requested page evidence, and a
  final answer containing the requested extraction.
- Browser control requires a `browser_type` call with the exact requested input
  followed by the submitting browser action, the required final URL or page
  state, and the requested screenshot or downloaded artifact.

Required artifact names are relative paths below the artifact root. Absolute
paths, parent traversal, and symlinks are rejected. A required artifact must be
a non-empty regular file, and a `.png` requirement must have a PNG signature.

Verifiers write exactly one binary reward key:

```json
{"reward": 0}
```

or:

```json
{"reward": 1}
```

They also write `checks.json` with stable check identifiers, pass/fail values,
and concise evidence. Missing tool calls, observations, final facts, URLs, or
artifacts are ordinary reward-zero outcomes. A malformed verifier fixture,
unreadable trajectory, or grader exception is an infrastructure failure: the
script exits non-zero without manufacturing a reward.

Latency, token usage, cost, tool-call count, and failed-tool count are
diagnostics only. Repeated Trials preserve Harbor's normal pass@k semantics
because the primary reward stays binary and task-local.

## Example Matrix

The repository includes:

- a minimal reusable Task template
- deterministic web-search, web-fetch, and browser-control examples driven by
  a canned harness and local fixtures
- live Psychevo web-search and web-fetch examples that use stable public pages
  and require an explicit live command

The live search and fetch cases use different instructions and evidence so a
model cannot pass both by returning the same memorized prose. Their verifier
still requires the respective real tool call and observation.

## Validation

Deterministic tests cover whitespace-bearing host paths, exact mount ownership,
safety-gate and unsupported-feature rejection, file transfer, environment
merging, timeout process cleanup, external harness invocation, trajectory
validation, runtime and hosted Psychevo NDJSON conversion, repeated assistant
lifecycles, same-call scoring, ordered browser input, rooted artifact
validation, and positive/negative verifier fixtures. At least one local
end-to-end Harbor Trial must exercise the custom environment, custom agent,
shared verifier, ATIF trajectory, reward, checks, and artifact collection.

Live validation is a separately reported opt-in run. Its result never replaces
deterministic package validation.
